# SQL Reset Nomor Pesanan Harian (`order_no` mulai dari #1 setiap hari)

Gunakan skrip SQL ini di **Supabase Dashboard → SQL Editor** apabila Anda ingin nomor pesanan (`No.`: `#1`, `#2`, dst.) otomatis kembali dimulai dari **#1 setiap hari pukul 00:00 WIB** (setelah `23:59` WIB), tanpa mengubah kode aplikasi maupun memerlukan cron job.

> **Cara kerja:** Fungsi `create_order` menghitung batas awal hari ini (`00:00:00 WIB`) sampai akhir hari ini (`< 00:00:00 WIB` esok hari), mengunci transaksi harian dengan `pg_advisory_xact_lock` agar aman bila dua kasir menekan Buat Pesanan secara bersamaan, lalu mengisi `order_no = coalesce(max(order_no), 0) + 1` untuk hari tersebut.

---

## 1. Aktifkan Reset Harian (mulai dari #1 setiap hari WIB)

Salin dan jalankan blok SQL berikut di Supabase SQL Editor:

```sql
-- 1) Izinkan create_order mengisi kolom order_no secara eksplisit
alter table public.orders
  alter column order_no set generated by default;

-- 2) Perbarui fungsi create_order agar order_no reset ke 1 setiap pergantian hari WIB
create or replace function public.create_order(p_order jsonb, p_items jsonb)
returns public.orders
language plpgsql
as $$
declare
  new_order public.orders;
  v_wib_date date;
  v_day_start timestamptz;
  v_day_end timestamptz;
  v_next_order_no bigint;
begin
  -- Tanggal berjalan dalam zona waktu WIB (Asia/Jakarta)
  v_wib_date := (now() at time zone 'Asia/Jakarta')::date;
  v_day_start := v_wib_date::timestamp at time zone 'Asia/Jakarta';
  v_day_end := (v_wib_date + 1)::timestamp at time zone 'Asia/Jakarta';

  -- Cegah nomor kembar jika dua pesanan masuk di milidetik yang sama
  perform pg_advisory_xact_lock(
    hashtext('cemal_cemul_daily_order_no_' || v_wib_date::text)
  );

  select coalesce(max(order_no), 0) + 1
  into v_next_order_no
  from public.orders
  where created_at >= v_day_start
    and created_at < v_day_end;

  insert into public.orders (
    order_no, customer_name, order_type, table_no, note,
    subtotal, discount_type, discount_value, discount,
    tax_percent, tax, total, payment_method
  ) values (
    v_next_order_no,
    p_order->>'customer_name',
    p_order->>'order_type',
    p_order->>'table_no',
    p_order->>'note',
    (p_order->>'subtotal')::int,
    p_order->>'discount_type',
    coalesce((p_order->>'discount_value')::int, 0),
    coalesce((p_order->>'discount')::int, 0),
    coalesce((p_order->>'tax_percent')::numeric, 0),
    coalesce((p_order->>'tax')::int, 0),
    (p_order->>'total')::int,
    p_order->>'payment_method'
  ) returning * into new_order;

  insert into public.order_items (order_id, menu_item_id, name, price, qty, variants, note)
  select new_order.id,
         nullif(i->>'menu_item_id','')::uuid,
         i->>'name',
         (i->>'price')::int,
         (i->>'qty')::int,
         coalesce(array(select jsonb_array_elements_text(i->'variants')), '{}'),
         i->>'note'
  from jsonb_array_elements(p_items) as i;

  return new_order;
end;
$$;

-- 3) Pastikan hak akses service_role tetap aktif
grant execute on function public.create_order(jsonb, jsonb) to service_role;
```

---

## 2. Catatan Penting

- Pesanan yang sudah ada **sebelum** skrip dijalankan tetap aman dan tidak diubah.
- Jika hari ini sudah ada pesanan (misalnya `#14`, `#15`), pesanan berikutnya di hari yang sama menjadi `#16`. Begitu lewat `23:59:59 WIB` (masuk `00:00:00 WIB` hari berikutnya), pesanan pertama otomatis dimulai lagi dari **`#1`**.
- Saat melihat **Riwayat Pesanan** rentang beberapa hari, dua hari yang berbeda bisa memiliki nomor `#1` masing-masing dan tetap dibedakan oleh kolom **Waktu (WIB)** serta ID unik.

## 3. (Opsional) Kembalikan ke Increment Terus-Menerus

Jika sewaktu-waktu ingin kembali ke penomoran berlanjut tanpa reset harian:

```sql
-- Sesuaikan sequence identity ke nilai order_no tertinggi saat ini
select setval(
  pg_get_serial_sequence('public.orders', 'order_no'),
  coalesce((select max(order_no) from public.orders), 1),
  true
);

alter table public.orders
  alter column order_no set generated always;
```
